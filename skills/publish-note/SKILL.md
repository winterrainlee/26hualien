# publish-note

화롄 경험 지도에서 **지역에 연결되는 노트**를 발행하는 스킬이다.

이 스킬의 목적은 기록을 빠르게 쌓는 것이다. 장소 데이터 정리, 좌표 조사, 사실 보강을 하지 않는다.

## 입력

필수 정보는 두 가지뿐이다.

- `title`: 노트 제목
- `region`: 노트를 연결할 지역

본문은 선택 사항이다.

- `body`: 노트 내용. 한두 줄 메모부터 긴 글까지 허용한다.

입력은 직접 전달된 텍스트일 수도 있고 로컬 초안 파일일 수도 있다.

로컬 초안은 사용자가 지정한 파일 또는 `.drafts/` 아래의 파일을 읽는다. 초안 파일은 원본으로 취급하고 수정하거나 삭제하지 않는다.

## 현재 지역

발행 전에 `map-data.js`의 `MAP_DATA.regions`를 읽어 현재 유효한 지역을 확인한다.

현재 기본 지역은 다음과 같다.

| regionId | 표시명 | 번체 |
| --- | --- | --- |
| `school` | 학교 | 志學村 |
| `city` | 시가지 | 花蓮市 |
| `shoufeng` | 소우펑 | 壽豐鄉 |
| `ruisui` | 루이수이 | 瑞穗鄉 |

표시명, 번체명, regionId 중 하나로 입력되어도 기존 지역과 명확히 대응되면 같은 지역으로 처리한다.

새 지역을 임의로 만들지 않는다. 기존 지역에 대응되지 않으면 사용자에게 물어본다.

## 발행 대상

노트는 `notes.js`의 `REGION_NOTES`에 추가한다.

본문이 없는 최소 형태:

```js
{id: 'unique-note-id', regionIds: ['ruisui'], title: '노트 제목'}
```

본문이 있는 형태:

```js
{
  id: 'unique-note-id',
  regionIds: ['ruisui'],
  title: '노트 제목',
  body: '첫 문단.\n\n두 번째 문단.'
}
```

### 본문 규칙

- 사용자가 본문을 주지 않았다면 `body`를 만들 필요가 없다.
- 본문이 있으면 원문의 의미와 말투를 유지한다.
- 맞춤법 교정이나 문장 윤문을 사용자가 요청하지 않았다면 과도하게 다시 쓰지 않는다.
- 문단 사이 빈 줄은 유지한다. 읽기모드는 빈 줄을 문단 구분으로 사용한다.
- 긴 본문을 짧게 요약해서 대체하지 않는다.
- 사용자가 적지 않은 사실을 보충하지 않는다.

### ID 규칙

- 기존 ID와 충돌하지 않는 고유한 ID를 만든다.
- 기존 노트의 ID는 변경하지 않는다.
- 사람이 읽을 수 있는 짧은 kebab-case를 우선한다.
- 자연스러운 영문 슬러그를 만들기 어렵다면 `note-<regionId>-<YYYYMMDD>-NN` 형식을 사용한다.
- 날짜는 내용의 사건일을 추측하지 말고, 별도 날짜 정보가 없으면 발행일을 사용한다.

## 처리 규칙

1. `notes.js`와 `map-data.js`를 먼저 읽는다.
2. 제목과 지역이 명확한지 확인한다.
3. 동일 제목·동일 지역의 기존 노트가 있는지 확인한다.
4. 본문이 제공되었다면 원문의 문단 구조를 유지해 `body`로 저장한다.
5. 중복이 아니면 `REGION_NOTES`에 새 항목을 추가한다.
6. 다른 파일의 장소 데이터는 수정하지 않는다.
7. 검증 후 커밋하고 푸시한다.

## 절대로 하지 않는 것

- 본문에 나온 장소를 자동으로 스팟으로 만들지 않는다.
- 주소, 좌표, 장소의 공식 명칭을 조사하지 않는다.
- 장소 존재 여부를 확인하기 위해 웹 검색하지 않는다.
- 노트를 특정 장소에 강제로 귀속시키지 않는다.
- 사용자가 말하지 않은 사실이나 경험을 만들어내지 않는다.
- 제목이나 본문을 과도하게 문학적으로 고치지 않는다.
- 새 지역을 자동 생성하지 않는다.
- `data/places.json` 또는 생성 지도 데이터를 수정하지 않는다.

## 애매할 때

다음 경우에만 사용자에게 질문한다.

- 제목이 없고 초안에서도 제목을 안정적으로 만들 수 없는 경우
- 지역이 없거나 둘 이상으로 해석되는 경우
- 같은 제목의 노트가 이미 있어 새 노트인지 중복인지 판단할 수 없는 경우

본문의 다른 표현이나 세부 사실이 애매해도, 사용자가 쓴 기록을 그대로 보존할 수 있다면 묻지 않는다.

여러 초안을 한 번에 처리할 때 일부만 애매하면 명확한 항목은 준비해 두고, 애매한 항목만 질문한다. 사용자가 부분 발행을 지시하지 않았다면 질문이 해결되기 전에는 해당 배치 전체를 커밋·푸시하지 않는다.

## 검증

수정 후 최소한 다음을 확인한다.

```sh
node --check notes.js
node --check app.js
```

가능하면 실제 페이지에서 다음도 확인한다.

- 해당 지역의 우하단 노트 개수가 1 증가한다.
- 노트 목록에 새 제목이 보인다.
- 제목을 누르면 상세 읽기모드가 열린다.
- 긴 본문은 팝업 내부에서 스크롤된다.
- `← 목록`으로 같은 지역의 노트 목록에 돌아온다.

## 커밋

사용자가 발행을 요청한 경우 검증 성공 후 현재 작업 브랜치에 커밋하고 푸시한다.

커밋 메시지는 짧게 작성한다.

예:

```text
Add Ruisui region note
```

## 완료 보고

완료 후 다음만 간단히 알려준다.

- 추가한 노트 제목
- 연결한 지역
- 본문 포함 여부
- 검증 결과
- 커밋/푸시 결과

노트 발행 과정에서 장소 구조나 지도 설계를 다시 설명하지 않는다.
