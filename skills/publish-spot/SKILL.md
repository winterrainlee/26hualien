# publish-spot

화롄 경험 지도에 **실제 장소 또는 실제 공간 영역을 스팟으로 추가**하는 스킬이다.

노트 발행과 달리 스팟은 지도상의 공간 객체다. 따라서 이름, 좌표, 지역 귀속을 추측하지 않는다. 애매하면 발행 전에 사용자에게 묻는다.

## 입력

사용자가 장소를 특정할 수 있는 정보를 받는다.

예:

- `東立茶行民宿을 루이수이 스팟으로 추가해줘`
- `華玉冰菓店, 瑞穗鄉中正北路 쪽. 지도에 넣어줘`
- 로컬 초안에 적힌 장소 목록

사용자가 이미 주소, 좌표, 공식명, 출처를 제공했다면 우선 사용하되 서로 모순되는 정보가 없는지 확인한다.

## 발행 전 반드시 읽을 파일

- `data/places.json`
- `map-data.js`
- `docs/map-design-principles.md`
- 필요하면 `README.md`

`map-data.js`는 생성 파일이다. 직접 편집하지 않는다.

## 현재 지역

`map-data.js`의 `MAP_DATA.regions`를 기준으로 regionId를 결정한다.

현재 기본 지역은 다음과 같다.

| regionId | 표시명 | 번체 | 의미 |
| --- | --- | --- | --- |
| `school` | 학교 | 志學村 | 동화대학·지학역 등 반복되는 학교 생활권 |
| `city` | 시가지 | 花蓮市 | 화롄시 도시 생활·외출 |
| `shoufeng` | 소우펑 | 壽豐鄉 | 향 전체의 마을·역사·농업·지역 탐색 |
| `ruisui` | 루이수이 | 瑞穗鄉 | 루이수이 지역 여행·조사 |

행정구역 포함 관계만으로 regionId를 기계적으로 정하지 않는다.

특히 `school`은 志學村이라는 생활권이고, `shoufeng`은 壽豐鄉 전체라는 별도 경험 범주다. 장소가 두 범주에 모두 자연스럽게 들어갈 수 있는데 현재 장소 모델은 단일 `regionId`를 사용하므로, 사용자의 의도가 분명하지 않으면 물어본다.

기존 지역에 대응되지 않는 장소를 발견했다고 새 지역을 자동 생성하지 않는다. 사용자가 새 지역 추가를 먼저 결정해야 한다.

## 저장 대상

원본 장소 데이터는 `data/places.json`이다.

새 스팟은 최소한 다음 필드를 가진다.

```json
{
  "id": "unique-place-id",
  "name": "한국어 표시명",
  "zh": "繁體中文 공식명 또는 통용명",
  "lon": 121.000000,
  "lat": 23.000000,
  "region": "지역 표기",
  "kind": "place",
  "text": "",
  "source": "검증에 사용한 출처",
  "regionId": "ruisui"
}
```

필요할 때만 다음 필드를 추가한다.

- `mapName`: 지도에서 긴 이름 대신 표시할 짧은 이름
- `address`: 확인된 주소
- `coordinateNote`: 좌표가 대표점임을 설명할 필요가 있을 때
- `childMap`: 별도 하위 지도가 실제로 계획된 경우

사용자가 설명 문장을 직접 주지 않았다면 `text`는 빈 문자열로 둔다. 장소의 경험이나 감상을 만들어 채우지 않는다.

## kind 규칙

### `place`

명확한 한 지점을 나타내는 대상에 사용한다.

예:

- 기차역
- 찻집
- 식당
- 숙소
- 상점
- 사찰
- 특정 건물

### `area`

점 하나가 아니라 범위 자체가 의미 있는 공간에 사용한다.

예:

- 캠퍼스
- 차 지구
- 공원·마을·시장 구역처럼 넓은 공간

`area`에 단일 좌표를 넣을 때는 정확한 경계를 뜻하지 않는다. 대표 좌표를 썼다면 `coordinateNote`에 그 사실을 남긴다.

## 장소 검증 순서

1. 사용자가 말한 장소가 `data/places.json`에 이미 있는지 확인한다.
2. 한국어명, 번체명, 주소, 좌표를 함께 비교해 중복 여부를 판단한다.
3. 장소의 정확한 정체성을 확인한다.
4. 가능한 경우 공식 웹사이트, 정부·기관 자료, 공식 사업자 정보 등 신뢰할 수 있는 출처를 우선한다.
5. 정확한 주소 또는 좌표를 확인한다.
6. 지역 경계와 사용자의 경험 범주를 함께 보고 `regionId`를 결정한다.
7. `place`인지 `area`인지 결정한다.
8. 필요한 필드만 작성한다.

검색 결과가 서로 충돌하면 임의로 하나를 고르지 않는다.

## 좌표 규칙

- 실제 확인된 경위도를 사용한다.
- 화면에서 보기 좋게 만들기 위해 좌표를 움직이지 않는다.
- 이름표가 겹쳐도 좌표를 수정하지 않는다.
- 정확한 좌표가 없고 대표점만 쓸 수 있는 영역이라면 그 사실을 `coordinateNote`에 기록한다.
- 주소만 확인되고 신뢰할 수 있는 좌표를 얻지 못했다면 억지로 발행하지 말고 사용자에게 알린다.

## 중복 규칙

동일 장소를 새 ID로 복제하지 않는다.

다음 중 하나라도 강하게 일치하면 기존 항목을 먼저 검토한다.

- 같은 번체 공식명
- 같은 주소
- 거의 같은 좌표
- 같은 시설의 한국어·중국어 이름 변형

기존 스팟이 맞다면 새 항목을 만들지 않는다. 기존 데이터 수정이 필요한 경우 변경 이유를 사용자에게 설명하고, 사용자의 요청 범위 안에서만 수정한다.

## 애매할 때 반드시 묻는 것

다음은 발행 전에 질문한다.

- 동명이인 장소가 둘 이상 있는 경우
- 주소나 좌표가 서로 다른 출처에서 충돌하는 경우
- 장소가 `school`과 `shoufeng` 중 어디에 속해야 하는지 경험 범주가 불명확한 경우
- `place`와 `area`의 선택이 데이터 의미를 바꾸는데 의도가 불명확한 경우
- 현재 지도에 없는 새 지역을 만들어야 하는 경우
- 사용자가 말한 장소와 검색된 장소가 같은 곳인지 확신할 수 없는 경우

사소한 표기 차이는 스스로 정규화해도 된다.

## 수정 절차

1. `data/places.json`을 수정한다.
2. JSON 문법과 중복 ID를 확인한다.
3. 생성 스크립트를 실행한다.

```sh
python3 scripts/build_map.py
```

4. 생성된 `map-data.js`와 관련 생성 파일을 확인한다.
5. 최소 검증을 실행한다.

```sh
node --check map-data.js
node --check app.js
node --check notes.js
```

6. 가능하면 `tests/mobile.html` 또는 실제 배포 페이지를 375×812, 320×740 정도의 모바일 폭에서 확인한다.
7. 새 스팟이 올바른 지역에 나타나는지, 기존 스팟과 겹칠 경우 클러스터가 정상 작동하는지 확인한다.
8. 검증 후 커밋하고 푸시한다.

## 생성 파일 규칙

- `map-data.js`의 경계, projected point, places 배열을 직접 손으로 고치지 않는다.
- 원본은 `data/places.json`에 둔다.
- 생성 결과가 이상하면 생성 스크립트나 원본 데이터를 고친 뒤 다시 생성한다.

## 절대로 하지 않는 것

- 좌표를 추측하거나 보기 좋게 이동하지 않는다.
- 사용자가 겪지 않은 경험을 `text`에 만들어 넣지 않는다.
- 기존 장소를 이유 없이 복제하지 않는다.
- 새 지역을 임의로 만들지 않는다.
- 검색만으로 불확실한 동명 장소를 확정하지 않는다.
- 지역 귀속이 애매한데 행정경계만 보고 임의 선택하지 않는다.
- 생성된 `map-data.js`를 원본처럼 직접 편집하지 않는다.

## 여러 장소를 한 번에 발행할 때

명확한 장소는 먼저 조사하고 데이터를 준비한다. 하나라도 정체성·좌표·지역 귀속에 중요한 모호성이 남아 있으면 해당 항목에 대해 질문한다.

사용자가 부분 발행을 지시하지 않았다면 질문이 해결되기 전에는 해당 배치 전체를 커밋·푸시하지 않는다.

## 커밋

사용자가 발행을 요청한 경우 검증 성공 후 현재 작업 브랜치에 커밋하고 푸시한다.

예:

```text
Add Dongli Tea House spot
```

또는 여러 장소라면:

```text
Add Ruisui trip spots
```

## 완료 보고

완료 후 다음을 간단히 알려준다.

- 추가하거나 수정한 장소
- 연결한 regionId
- 사용한 좌표/주소 출처
- 검증 결과
- 커밋/푸시 결과

불필요하게 장소 소개문이나 여행 설명을 덧붙이지 않는다.
