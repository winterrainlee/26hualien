# 화롄 경험 지도 — 지역 탐색과 기록 구성 원칙

합의일: 2026-09-27 (Asia/Taipei)

이 문서는 이후 지도 구현과 장소·기록 추가의 기준이다. 지역 탐색 구현 및 최신 합의를 함께 기록한다.

## 1. 지도의 목적

화롄에서 머무는 동안 어디를 다니고, 무엇을 경험하고 느꼈는지를 공간으로 담는다. 반복되는 생활, 도시 외출, 주말 여행, 지역 조사 기록을 함께 수용한다. 장소의 실제 위치와 공간적 관계를 보존한다.

## 2. 처음에는 네 지역으로 시작한다

| 지역 | 중심 관심 | 우선 연결할 장소 | 지역을 눌렀을 때의 범위 |
| --- | --- | --- | --- |
| 학교 | 연수 생활과 반복되는 일상을 담는다. | 동화대학, 지학역을 연결한다. | 志學村 경계 전체로 확대한다. |
| 시가지 | 화롄시에서의 외출과 도시 경험을 담는다. | 화롄 기차역을 연결한다. | 花蓮市 경계 전체로 확대한다. |
| 소우펑 壽豐 | 향 전체의 마을·역사·농업·지역사회를 살펴본다. | 이후 방문·조사하는 마을과 장소를 추가한다. | 壽豐鄉 전체가 보이도록 확대한다. |
| 루이수이 | 주말 여행과 지역 조사 기록을 담는다. | 루이수이역, 농회 시장, 우허 차 지구를 연결한다. | 瑞穗鄉 경계 전체로 확대한다. |

학교는 캠퍼스 자체보다 넓은 생활권이다. 동화대학 캠퍼스 지도는 학교 지역 안에서 동화대학을 선택했을 때 들어가는 하위 지도다.

지역은 서로 배타적인 행정구역 분할이 아니다. 학교와 소우펑은 공간적으로 겹칠 수 있다. 학교는 생활 경험, 소우펑은 지역 자체에 초점을 맞춘다. 같은 장소와 기록이 필요에 따라 둘 이상의 지역과 연결될 수 있다.

예를 들어 지학역을 이용한 일상은 학교에, 지학 마을과 철도의 관계를 조사한 기록은 소우펑에 연결할 수 있다. 이를 위해 지학역이라는 장소를 복제하지 않는다.

## 3. 탐색 흐름

기본 흐름은 다음과 같다.

1. 대만 본섬에서 연록색 화롄현을 선택한다.
2. 화롄현 전체 지도에서 학교·시가지·소우펑·루이수이의 이름표를 선택한다.
3. 선택한 지역으로 지도가 확대되고, 그 지역에 연결된 장소들이 나타난다.
4. 개별 장소를 누르면 기록을 열거나, 준비된 하위 공간 지도로 들어간다.

화롄현 전체 화면의 주된 선택 대상은 네 지역이다. 개별 장소 여섯 개를 동시에 구분하도록 요구하지 않는다. 현 안의 행정경계는 공간을 이해하는 배경이며, 행정구역마다 자동으로 클릭 기능을 붙이지 않는다.

지역 진입은 같은 지도의 해당 범위를 확대하는 방식으로 구현한다. 확대 전후의 공간적 연결을 알아볼 수 있게 부드럽게 전환한다. 지역 화면의 제목은 선택한 지역 이름으로 바뀌고, `← 화롄현`으로 돌아갈 수 있다.

기록 카드를 닫으면 탐색하던 지역과 확대 상태를 유지한다. 하위 지도에서 돌아올 때도 직전 지역의 범위와 위치를 복원한다. 화롄현에서는 대만 화면으로 돌아갈 수 있다.

## 4. 지역 이름표와 장소의 점을 구분한다

현 전체에서는 지역을 이름표로 표시한다. 이름표는 특정 건물이나 정확한 좌표 하나를 뜻하는 점과 시각적으로 구분한다. 학교와 소우펑처럼 겹치는 지역도 각각 선택할 수 있도록 이름표 위치를 조정할 수 있다.

학교는 志學村, 시가지는 花蓮市, 소우펑은 壽豐鄉, 루이수이는 瑞穗鄉의 실제 행정경계를 사용한다. 구현 편의를 위해 동화대학과 지학역 모두 학교(志學村)에 연결한다. 소우펑에는 현재 별도 장소를 연결하지 않는다. 학교 전체 부지가 촌 경계에 완전히 포함된다는 지적 측량 판정을 뜻하지 않는다.

소우펑 등 실제 행정경계가 있는 지역은 검증된 데이터를 사용할 수 있다. 영역을 색칠하는 구체적인 방식은 후속 구현에서 결정한다. 최초 지역 진입 수단은 이름표를 기준으로 한다.

## 5. 실제 장소 좌표를 고정한다

개별 장소의 점은 실제 경위도를 현재 지도에 투영한 위치에 놓는다. 점이 겹친다는 이유로 장소 좌표나 표시 위치를 옮기지 않는다. 같은 지도 투영과 화면 변환을 지도 윤곽과 점에 일관되게 적용한다.

이름표의 위치·길이·표시 여부는 조정할 수 있다. 점의 위치와 이름표의 위치는 별도로 다룬다. 지도에서는 짧은 이름을 사용할 수 있고, 선택한 장소나 기록 카드에서는 한국어·중국어 전체 이름을 확인할 수 있게 한다.

구역을 대표하는 점은 출입구의 정확한 위치나 영역 경계를 뜻하지 않는다. 동화대학은 후문이 아닌 캠퍼스 대표 장소로 유지한다. 정확한 경계·건물 자료가 준비되기 전에는 캠퍼스 지도를 임의로 그리지 않는다.

## 6. 자동 묶음은 겹침을 해결할 때만 사용한다

지역 화면으로 확대해도 개별 선택이 어려운 장소에 자동 묶음을 적용한다. 자동 묶음은 화면에 따라 잠깐 생기는 표시이며, 이름과 정체성이 유지되는 지역과 별개의 개념이다.

- 실제 좌표를 현재 화면의 위치로 변환한 뒤, 화면상 거리를 기준으로 겹침을 판단한다.
- 충분히 떨어진 장소는 개별 점으로 표시한다. 같은 지역 소속이라는 이유만으로 묶지 않는다.
- 확대·축소와 화면 크기 변경에 따라 묶음을 다시 계산한다. 실제 거리만으로 영구적인 묶음을 만들지 않는다.
- 가까운 점이 연쇄적으로 이어졌다는 이유로 멀리 떨어진 장소까지 하나로 합치지 않는다. 묶음 전체가 차지할 수 있는 범위를 제한한다.
- 묶음은 숫자가 든 원 등으로 개별 장소 점과 구분한다. 숫자는 기록 수나 방문 횟수가 아니라 장소 수를 뜻한다.
- 묶음을 누르면 구성 장소를 확인할 수 있는 범위로 자동 확대한다. 이름표와 터치 영역도 함께 확인한다.
- 같은 건물처럼 확대만으로 분리하기 어려운 장소는 짧은 선택 목록으로 제공한다. 구분을 위해 점을 가짜 위치로 펼치지 않는다.

점 중심 사이 약 44~48 CSS 픽셀은 앞선 논의에서 제안한 초기 조정값이다. 확정 규격이 아니며, 실제 모바일 화면에서 점 크기·터치 영역·이름표·확대 동작을 확인한 뒤 결정한다. 묶음 최대 범위와 확대 한계 역시 후속 검토 사항이다.

묶음 여부와 개별 장소의 진입 방식은 별개다. 동화대학이 지학역과 묶여 있을 때는 먼저 확대하고, 동화대학이 개별 장소로 드러나면 준비된 캠퍼스 지도에 진입한다.

## 7. 지역·장소·기록·화면상의 묶음을 분리한다

| 개념 | 역할과 유지 원칙 |
| --- | --- |
| 지역 | 함께 탐색하고 경험·조사 기록을 모으는 지속적인 단위다. 화면 축척이 달라져도 유지된다. |
| 장소 | 실제 좌표 또는 검증된 영역을 가진 대상이다. 반복 방문이나 복수 지역 연결 때문에 복제하지 않는다. |
| 기록 | 장소 하나, 여러 장소, 지역 전체에 연결할 수 있다. 반드시 점 하나에 귀속시키지 않는다. |
| 자동 묶음 | 현재 화면에서 장소 선택을 돕는 일시적인 표시다. 기록의 소속 대상이나 새로운 지역이 되지 않는다. |

지학역을 열 번 이용해도 점은 하나이고 기록이 쌓인다. 루이수이에서 보낸 주말 기록은 역·시장·차 지구 여러 곳에 연결할 수 있다. 우허의 차 산업이나 소우펑의 역사 조사는 특정 가게 대신 지역 전체에 연결할 수 있다.

학교·시가지·소우펑·루이수이를 서로 다른 고정 형식의 페이지로 제한하지 않는다. 같은 지역 화면 구조 안에서 생활 기록, 방문일별 기록, 지역 조사 등이 쌓일 수 있게 한다. 지역별로 무엇을 먼저 보여 줄지는 실제 기록이 쌓인 뒤 조정한다.

## 8. 여행지가 늘어나면 지역을 추가한다

처음부터 화롄현의 모든 향·진·시를 지역으로 만들지 않는다. 현재 합의한 네 지역으로 시작하고, 이후 새로운 곳을 여행하면 그때 필요한 지역을 추가한다. 지역 조사 기록을 모을 필요가 생기는 경우에도 같은 기준으로 확장한다.

새 지역을 추가할 때는 다음 내용을 정한다.

1. 사용자가 알아볼 지역 이름과 그 지역에서 모으려는 경험·조사의 초점을 정한다.
2. 연결할 장소와 지역 전체의 기록을 정한다. 기존 장소가 있다면 그대로 재사용한다.
3. 지역을 선택했을 때 보여 줄 확대 범위를 정한다. 장소가 하나뿐이거나 아직 없어도 과도하게 확대하지 않도록 범위를 명시할 수 있어야 한다.
4. 기존 지역과의 공간적 중첩을 허용하고, 현 전체에서 이름표를 구분해 선택할 수 있는지 확인한다.

장소 수가 늘거나 자동 묶음이 생겼다는 이유만으로 새로운 지역을 자동 생성하지 않는다. 장소의 겹침 처리는 자동화하되, 어떤 공간을 하나의 경험 지역으로 볼지는 사용자가 정한다.

## 9. 디자인과 후속 구현 검증

현재의 베이지·연록색 파스텔과 모바일 세로 화면 구성을 유지한다. 표제 아래 회색 설명과 화면 하단 안내 문구, 점 연결선은 다시 추가하지 않는다. 이름표·제목·돌아가기 등 직접 조작할 수 있는 요소로 탐색을 이해하게 한다.

후속 구현 완료는 코드 수정이나 배포 성공만으로 판단하지 않는다. 실제 배포된 페이지에서 최소 375px·320px 폭으로 다음 항목을 확인한다.

- 대만 → 화롄현 → 각 지역의 전환과 돌아가기가 정상적으로 작동한다.
- 학교와 소우펑을 별도로 선택할 수 있고, 아직 장소가 없는 지역도 의미 있는 범위로 열린다.
- 장소 점이 원래 좌표에 놓이며, 점·이름표의 겹침 때문에 다른 장소가 잘못 선택되지 않는다.
- 필요한 묶음이 확대하면 분리되고, 반복 방문 때문에 점이나 장소 수가 늘어나지 않는다.
- 카드 닫기와 하위 지도 복귀 후 이전 탐색 범위를 유지한다.
- 가로 넘침, 잘린 이름표, 페이지 콘솔 오류와 실패한 필수 요청이 없다.

## 10. 현재 구현 상태

현 전체에서 네 지역 이름표를 선택하고 해당 실제 행정경계로 확대한다. 장소 표시 오프셋은 제거했으며 지도와 장소에 같은 투영·화면 변환을 적용한다. 가까운 장소는 화면 거리로 묶고 선택하면 확대한다. 카드 닫기는 확대 상태를 유지하며 돌아가기는 확대 전 지역, 현, 대만 순으로 복귀한다.

학교와 지학역은 학교(志學村)에 연결한다. 소우펑은 빈 지역 지도로 시작한다. 신규 지역은 여행할 때 명시적으로 추가한다. 동화대학의 childMap은 planned 상태이며 캠퍼스 지도는 후속 작업이다. 현재는 기존 기록 카드를 연다.

2021.9.20 Taiwan Atlas를 고정해 사용한다. 志學村은 villages-10t.json에서 추출한 GeoJSON으로 보존한다. 임의로 그린 경계와 외부 런타임 의존성은 사용하지 않는다.

### 지학촌과 소우펑의 포함 관계

현 전체 지도에서는 소우펑 면을 먼저 그린 뒤 지학촌을 더 짙은 초록색으로 덧그린다. 지학촌 상세에서는 기존 확대 범위를 유지하면서 배경에 소우펑 외곽선을 별도로 표시한다. 확대 화면 밖으로 이어지는 경계는 지도 가장자리에서 잘리며, 전체 소우펑 범위는 소우펑 지역 화면에서 볼 수 있다.

### 지역 노트와 방문 표시

지역 상세 지도 우하단에 테두리 없이 ‘현재 지역 이름 노트 N개’를 표시한다. 노트 원본은 `notes/*.md`에 1노트 1파일로 저장하며, 파일명은 안정적인 노트 ID로 사용한다. 각 파일의 필수 메타데이터는 `title`과 `regions`다. `scripts/build_notes.py`가 이 원본들을 브라우저용 `notes.js`로 생성하므로 `notes.js`는 직접 편집하지 않는다. N은 생성된 `regionIds`의 현재 범주에 직접 연결된 노트 수다. 학교와 소우펑은 별도 범주이며 자동 합산하지 않는다. 선택하면 제목 목록이 열리고, 제목을 누르면 같은 dialog 안에서 상세 읽기모드로 전환한다. 상세 읽기모드는 긴 본문을 위해 높이를 넓게 사용하고, 상단의 `← 목록`과 닫기 버튼은 스크롤 중에도 고정한다. 본문의 빈 줄은 문단 구분으로 표시하며, 본문이 없는 노트는 빈 상태 문구를 보여 준다. Markdown 원본은 향후 노트 간 링크·태그 등을 확장할 수 있도록 그대로 보존한다. 현재 루이수이 3개는 명시된 테스트 노트이며 실제 여행 내용을 생성하지 않는다. 기존 장소 점과 카드는 유지한다.

화롄현에서 학교 이름표와 지학촌 면만 선으로 연결한다. 개별 장소 사이 연결선은 없다. 루이수이 이름표 옆 단색 기차 아이콘은 기차로 방문했다는 뜻이다. 아이콘은 Lucide train-front SVG를 로컬에 보존한다. 팝업 닫기 후 장소 포커스는 복원하지만 사각 테두리는 표시하지 않는다.

### 주변 행정구역 이름

소우펑·루이수이 상세에서는 경계를 공유하는 인접 향·진·시의 번체 이름을 옅게 표시한다. 지도에 보이는 부분의 면적 중심을 기준으로 하며, 글자가 해당 구역 안에 들어갈 공간이 부족하면 표시하지 않는다. 이름은 클릭 대상이 아니다. 인접 관계와 이름 위치는 고정 Taiwan Atlas에서 빌드하며 손으로 지정하지 않는다.
